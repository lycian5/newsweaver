# COA NEWS 소재 수집 운영 기준

상황 점검과 코드 리뷰는 [`REVIEW.md`](REVIEW.md)를 먼저 봅니다.

## 1. 목적

### 수집 분류와 검색 단계

- 기존 `AI 비즈니스`, `창업·부업`, `정책·지원사업`에 `소상공인 경제`, `지역 상권`, `마케팅·유통`, `현장 이슈`를 추가한다.
- 키워드는 주체·업종·이슈·지역/기관 축과 동의어 그룹으로 관리하되, 모든 조합을 생성하지 않고 제한된 템플릿만 사용한다.
- `explore`: RSS·영상 등에서 폭넓게 신호를 찾는다.
- `precision`: Exa에서 주제 맥락과 동의어를 포함해 관련도를 높인다.
- `verification`: 공식 도메인과 PDF/HWP/HWPX 첨부자료를 대상으로 사실을 확인한다.
- 원문 행에는 검색 단계(`query_stage`)와 출처 계층(`source_layer`: signal/official/data)을 기록한다.

이 시스템의 1차 목표는 완성 기사를 자동 생산하는 것이 아니라, 다양한 기사 소재를 넓게 수집하고 수치화해 편집자가 빠르게 판단할 수 있게 하는 것입니다. 원시 수집량은 넉넉하게 유지하되 중복 제거, 출처 신뢰도, 시의성, 공식 근거 여부로 후속 처리 대상을 줄입니다.

## 2. 단일 운영 흐름

1. **기초 수집**: 제목, URL, 출처, 발행 시각, 검색 키워드, 짧은 원문 설명을 저장합니다.
2. **정규화와 중복 제거**: URL과 제목을 정규화하고 동일 사건 후보를 묶습니다.
3. **점수화**: 시의성, 출처 품질, 공식 출처, 교차 확인 수, 키워드 관련성을 계산합니다.
4. **클러스터링**: 같은 사건을 하나의 소재 묶음으로 만들고 대표 제목과 근거 목록을 구성합니다.
5. **리서치 브리프**: 규칙으로 요약·기간·출처를 본 뒤, Agent Reach 수집이 끝나면 AI가 요약을 근거와 대조해 가능/보류로 다시 나눕니다. 작성 가능이면 초안으로 넘깁니다.
6. **기사 초안 작성**: 작성 가능으로 넘긴 소재만 등록용 기사 준비 화면에서 실제 본문을 작성합니다. AI 작성·이미지는 이 화면에서만 선택 호출합니다.
7. **검토와 등록**: 편집장 검토와 등록용 승인을 거친 최종본만 패키지로 내보내 플랫폼에 수동 등록합니다.

원시 수집 단계에서는 OpenAI를 호출하지 않습니다. Agent Reach가 URL을 저장하고 클러스터를 만든 뒤에만 요약 검토로 OpenAI를 호출합니다. 소재를 선택하기 전에는 장문 기사도 생성하지 않습니다.

## 3. 수집 채널과 범위

| 계층 | 실행 | 기본 범위 | 역할 |
|---|---|---:|---|
| Vercel 전날 마감 수집 | 매일 07:10 KST가 속한 시간대 | 18개 키워드 | 전날 00:00~24:00 KST에 발행된 Naver·Google·Bing 뉴스와 국내 언론 RSS, 정책 자료 수집 |
| 조건부 누락 보정 | 매일 09:00 KST가 속한 시간대 | 전날 대상 | 주 수집 실패·부분 실패·7일 중앙값 대비 저수집일 때만 재수집 |
| VPS Agent Reach | 매일 16:30 KST | 54개 키워드 | Exa, 공식 기관, 국내·해외 RSS와 선택형 Reddit. 저장 후 중복 제거·점수·클러스터·브리프 갱신, 이어서 요약 AI 검토 |
| 주제 제안 cron | 매일 17:30 KST | 보조 | Vercel `/api/cron/suggest`. 브리프 큐와 무관한 주제 제안. 운영 본선이 아님 |

Vercel 전날 마감 수집은 핵심 6개와 순환 12개를 사용합니다. 키워드 검색은 Naver, Google, Bing을 함께 호출하고, 국내 언론 RSS는 실행당 한 번만 받은 뒤 선택된 키워드와 맞는 항목만 남깁니다. 검색 결과를 저장하기 전에 KST 기준 전날 발행분으로 제한하며, 발행일이 없는 공식 정책 자료는 단서 유실 방지를 위해 포함합니다. Daum 검색 RSS는 공개 엔드포인트가 없어 사용하지 않습니다. Agent Reach는 핵심 12개와 순환 42개를 사용합니다. 활성 키워드가 54개보다 늘어나면 핵심 키워드는 고정하고 나머지 풀을 날짜별로 순환합니다.

조건부 누락 보정의 기본 하한은 20건이며, 최근 정상 주 수집 7회의 저장 건수 중앙값 60%와 비교해 더 큰 값을 기준으로 사용합니다. 주 수집이 아직 실행 중이거나 같은 날짜의 보정이 이미 성공했으면 재실행하지 않습니다. Vercel Hobby에서는 cron 분 단위 실행이 보장되지 않으므로 07시 주 수집과 09시 보정을 서로 다른 시간대로 분리합니다.

YouTube와 GitHub는 인증 및 쿠키 상태가 검증된 뒤 선택적으로 사용합니다. Reddit은 승인된 OAuth 읽기 전용 API 자격증명을 VPS에만 설정한 뒤 선택적으로 사용합니다. RSS는 해외 기술·창업 피드와 주수집과 같은 국내 언론 피드를 함께 사용하며, 원문 보강은 `AGENT_REACH_JINA_ENRICH=true`일 때에만 수행합니다. 공식 검색은 카테고리별로 공정위·통계청·한은 등 검증 도메인을 포함합니다. 소셜·영상 자료는 단서로 취급하며, 기사 근거는 원문과 공식 자료로 다시 확인합니다.

한 번의 Agent Reach 실행에서는 RSS 피드를 URL별로 한 번만 내려받아 모든 키워드에 재사용합니다. Exa와 공식 출처 검색은 키워드별로 실행하되 결과 수 상한을 적용합니다.

Agent Reach 자동 수집 시간과 사용 여부는 `/vps-collector`에서 설정합니다. 이 화면의 1순위는 오늘 자동 수집 상태입니다. 채널·결과 수·직접 키워드는 수동 재수집에만 쓰이며 자동 일정을 바꾸지 않습니다. n8n은 5분마다 `collection_schedules`를 확인하며 설정한 KST 시각에만 실행합니다.

### 3.3 운영 화면

관리자 세션 하나로 아래 화면을 씁니다.

| 화면 | 경로 | 역할 |
|---|---|---|
| 수집 운영 | `/vps-collector` | 오늘 주수집·보정·Agent Reach 상태, 오늘 키워드, 16:30 일정, 수동 재수집 |
| 리서치 브리프 | `/research-briefs` | 기본 큐는 오늘 작성 가능 소재. AI 검토 후 가능/보류로 나눠 바로 초안 전환 |
| 기사 초안 준비 | `/coanews-draft` | 본문 작성, 등록용 승인, ZIP 내보내기 |

리서치 브리프의 필터는 접혀 있습니다. 기본 목록은 **최근 수집 24시간**(`last_seen_at`)입니다. 작성 가능의 기간 규칙은 **발행일 7일**(정책은 공고 유효 또는 14일)이라 두 시계가 다릅니다. 어제 들어온 유효 소재를 보려면 필터를 7일로 넓히면 됩니다. 수집 상태 카드는 수집 운영 화면으로 연결됩니다. 공개 랜딩(`/`)은 운영 수집 제어가 아닙니다.

화면 위 카드의 **작성 보류**는 규칙·AI 판정입니다. 그 옆 **보류**는 담당자가 버튼을 눌러 잠시 빼 둔 상태입니다. 둘이 다릅니다.

### 3.1 현재 수집 출처

주수집 키워드 검색:

| 출처 | 모듈 | 비고 |
|---|---|---|
| Naver 뉴스 API | `lib/naver.js` | 키워드당 최신 검색 |
| Google 뉴스 RSS | `lib/googleNews.js` | `hl=ko&gl=KR` |
| Bing 뉴스 RSS | `lib/bingNews.js` | `ko-KR`, 추적 URL은 원문으로 변환 |

주수집 보강:

| 출처 | 모듈 | 비고 |
|---|---|---|
| 국내 언론 RSS 10곳 | `lib/koreanNewsRss.js` | 실행당 1회 수신 후 선택 키워드와 매칭 |
| 정책 목록 페이지 | `lib/policySources.js` | 정책브리핑, 중기부, 고용부, 기업마당, 소진공, K-Startup |
| 공공데이터 API | `lib/publicDataSources.js` | 기업마당, K-Startup |

국내 언론 RSS 기본 목록은 연합뉴스, 한국경제 IT, 매일경제, 조선비즈, 전자신문, 뉴시스, 플래텀, 벤처스퀘어, 바이라인네트워크, 더피알입니다. Agent Reach는 같은 목록을 해외 기술·창업 RSS 뒤에 합칩니다.

Agent Reach 공식 검색 도메인에는 기존 부처·지원기관에 공정위(`ftc.go.kr`), 통계청(`kosis.kr`, `kostat.go.kr`), 한은(`bok.or.kr`), 기재부(`moef.go.kr`)가 포함됩니다.

사용하지 않는 후보:

- 다음/카카오 뉴스 RSS: 공개 검색·섹션 RSS가 없어 넣지 않음
- 빅카인즈 API: 신청·쿼터·비용 확인 전이라 넣지 않음

## 4. 점수와 선별 기준

- 공식 기관 자료와 원문은 높은 출처 점수를 부여합니다.
- 최근 발행, 여러 독립 출처의 일치, 구체적 수치와 일정이 있는 소재를 우선합니다.
- 단일 보도자료 복제, 제목만 다른 중복 기사, 광고성 문서는 감점합니다.
- 공식 확인이 없거나 상충하는 내용은 `needs_verification`으로 표시합니다.
- 수집량이 많아도 동일 사건은 하나의 클러스터로 합쳐 편집 부하를 줄입니다.

대량 수집의 성과는 원시 건수만으로 판단하지 않습니다. 일별로 원시 수집 건수, 고유 URL 수, 중복 제거율, 사건 클러스터 수, 공식 출처 포함률, 브리프 전환율, 소재 채택률을 함께 봅니다.

## 5. 리서치 검증 기준

리서치 브리프는 완성 기사나 게시 가능한 원고가 아닙니다. 목록에서 가능 여부와 두 줄 요약으로 고르고, 상세에서 요약·핵심 표·묶인 근거를 확인합니다.

판정:

| 표시 | 뜻 | 다음 행동 |
|---|---|---|
| 작성 가능 | 필수 출처를 통과했고, AI 검토가 있으면 요약이 근거와 맞음 | 바로 기사 작성 |
| 작성 가능 · 원문 확인 | 출처는 되나 원문 설명이 없고 아직 AI 검토 전 | 원문 확인 또는 수집 후 자동 검토 대기 |
| 작성 보류 | 규칙 경고이거나 AI가 확인 필요·근거 부족으로 판단 | 브리프 큐에 남김. 사람이 누른 보류 상태와는 다름 |
| 보류 | 담당자가 보류 버튼을 누름 | 나중에 재개 |
| 작성 불가 | 제목, 근거 URL, 사용 가능 출처(A~C) 없음 | 초안 차단. AI가 바꿔도 불가 |

기간은 수집일이 아니라 발행일(`published_at`)과 사건일(`event_date`)을 씁니다. 뉴스·창업·현장은 7일 안, 정책·지원은 공고일이 남았거나 14일 안이어야 규칙상 가능 후보입니다. 그다음 AI 검토가 가능/보류를 다시 나눕니다. 본문에서 잘라 낸 날짜 문자열은 판정에 쓰지 않습니다.

요약은 규칙으로 만듭니다. Agent Reach가 끝난 뒤 갱신된 브리프만 AI가 검토하며, 같은 요약은 다시 호출하지 않습니다. 기본 모델은 OpenAI `gpt-5-mini`입니다.

## 6. 비용 통제

- 원시 수집, 정규화, URL 중복 제거, 브리프 요약 작성에는 LLM을 사용하지 않습니다.
- AI는 수집 후 요약 검토와, 초안 화면의 작성·이미지 보조에만 씁니다.
- Exa 결과 수, RSS 결과 수, 처리 키워드 수는 환경변수로 제한합니다.
- 긴 본문 수집은 상위 점수 소재에만 수행합니다.
- 정밀 리서치 방식은 법적·정책적 위험이 높거나 다수 출처가 상충하는 선택 소재에만 적용합니다.

## 7. 상태와 권한

- `raw_articles`, `event_clusters`, `editorial_drafts`의 상태는 내부 작업 상태입니다. `editorial_drafts`는 등록용 기사 초안의 핵심 내용과 검토 상태를 보존합니다.
- `pending_editor_approval`은 내부 편집장 검토대기이며 `approved`는 등록용 승인입니다. 두 상태 모두 신문 플랫폼에 실제 등록됐다는 뜻이 아닙니다.
- 플랫폼 등록, 승인, 노출 상태는 플랫폼에서 확인한 값으로 별도 기록해야 합니다.
- 최종 승인과 반려는 편집장 권한이며 상태 변경 시 작업자, 이전 상태, 새 상태, 시각, 메모를 감사 이력에 남기는 것을 운영 원칙으로 합니다.
- 플랫폼에 JSON 또는 CSV 가져오기 기능이 제공되기 전에는 자동 게시를 시도하지 않습니다.

## 8. 자동화 소유권

- Vercel cron과 VPS Agent Reach가 운영 수집의 기준입니다.
- `n8n/workflow_collect.json`과 `n8n/workflow_suggest.json`은 구형 보관본이며 활성화하지 않습니다.
- Vercel `/api/cron/suggest`(17:30 KST)는 주제 제안 보조이며 브리프 큐와 무관합니다.
- n8n에서는 Agent Reach runner 호출과 운영 보조만 수행합니다.
- n8n 이미지는 `2.30.7`로 고정하고 업그레이드 전 백업과 복원 시험을 수행합니다.
